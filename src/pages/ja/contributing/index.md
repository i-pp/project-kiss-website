## 対象を絞った改善を提案する

誤記の修正、翻訳の改善、アクセシビリティの修正、開発上の説明の改善を歓迎します。プロジェクトの対象やプロダクトの説明を変える場合は、範囲を広げる前にIssueで根拠と理由を示してください。

サイトの質問・提案は[サイトのIssue](https://github.com/i-pp/project-kiss-website/issues)へ。IssueやPull Requestに、認証情報、非公開ログ、機密資料を含めないでください。

## Pull Requestで提案する

1. ブランチで作業し、変更を目的に必要な範囲に絞る。
2. 対応する日本語・英語のページを一緒に更新する。
3. Node.js 24、npm、Python 3があるチェックアウトで、`npm ci`と`npm run verify`を実行する。開始手順は[サイトの開発ガイド](/ja/docs/#このサイトを開発する)を参照する。
4. 狭い画面と広い画面、キーボード操作、文字拡大で表示と操作を確かめる。
5. 変更内容、理由、実施した検査、残る限界を記載する。

プロダクトの説明では、目標と検証済みの実装を区別します。リリース日、性能、対応プラットフォームを推測で補いません。

## ブランドの原本を守る

提供済みのProject-KISSとProject-AceISのPNGを、元のバイト列を変えずに使います。縦横比と透過を保ち、無関係な変更でロゴを再描画、変色、差し替えしません。

## 権利とレビュー

このサイトのリポジトリ全体に適用するOSSライセンスは、現在設定していません。プロジェクト名とロゴの既存の権利は保持されます。投稿する権限のある資料だけを提出してください。掲載によってロゴの利用許諾が新たに与えられるものではありません。

公開前に技術レビューと編集レビューを行います。Pull Requestの作成やビルドの成功だけで、本番公開、DNS変更、認証情報の変更が許可されることはありません。
